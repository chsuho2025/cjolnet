## 작업 결과

카카오엔터테인먼트 인턴으로 음악 도메인 발음사전 제작과 TTS 품질 검수에 참여했습니다. 영어와 숫자가 포함된 곡명·아티스트명 약 3만 5천 개를 후보로 정리하고, 초기 약 3,500건의 발음을 공개 자료로 직접 조사했습니다. 등록 뒤에는 고유명사가 들어간 추천 문장을 재생해 발음과 끊어읽기를 확인했습니다.

## 1. 화면의 이름을 음성으로 정확하게 전달하기

음악 추천 문장에는 곡명, 아티스트명, 클래식 작품 번호가 계속 등장합니다. 화면 표기가 정확해도 TTS가 낯선 방식으로 읽으면 사용자는 어떤 음악을 소개하는지 바로 알아듣기 어렵습니다.

음악 고유명사는 일반적인 영문 읽기 규칙만으로 처리하기 힘든 경우가 많았습니다. 숫자와 기호가 철자를 대신하거나, 아티스트가 통상적인 발음을 벗어난 이름을 사용하기도 합니다. 국내에서 널리 쓰는 이름과 원어 발음이 다른 사례도 있습니다. 클래식 곡명은 작품명·조성·곡 번호·작품 번호가 한 문장 안에 함께 들어가므로 숫자의 역할과 호흡 위치까지 구분해야 했습니다.

이 업무에서는 `표기를 어떻게 읽을지`와 `문장 안에서 어떻게 들리는지`를 나눠 확인했습니다. 발음사전에 정답을 적는 데서 끝내지 않고 실제 서비스 문장에 적용된 음성을 다시 들었습니다.

## 2. 발음뿐 아니라 판단 근거를 함께 기록

초기 약 3,500건은 곡명과 아티스트명을 하나씩 검색해 국내 통용 표기, 언어권과 공개된 발음 자료를 확인했습니다.

| 기록 항목 | 실제 활용 |
|---|---|
| 검색어·확인 자료 | 같은 항목을 다른 사람이 다시 확인 |
| 국적·활동 정보 | 우선 확인할 언어권과 통용 발음 탐색 |
| 국내 통용 표기 | 원어 읽기와 서비스 이용자가 아는 이름 비교 |
| 선택 이유·예외 | 비슷한 표기를 일관되게 처리 |
| 처리 시간 | 수동 조사의 병목과 자동화 후보 확인 |

발음만 남기면 나중에 결과가 달라졌을 때 왜 그 발음을 선택했는지 알기 어렵습니다. 확인 자료와 판단 이유를 같이 적어 신규 항목과 재검수에도 쓸 수 있는 기록으로 만들었습니다.

## 3. 수동 조사에서 반복 패턴과 예외를 분리

약 3,500건을 조사하자 다음 항목에서 반복되는 구조가 보였습니다.

- `Op.`, 곡 번호, 조성, 작품목록 번호처럼 역할이 정해진 클래식 표기
- 장르 안에서 숫자와 알파벳을 관용적으로 쓰는 이름
- 공식 자료와 국내 유통 표기에서 같은 발음을 확인할 수 있는 항목
- 같은 언어권에서 반복되는 철자와 음가

반면 `6LACK`, `deadmau5`, `Tech N9ne`처럼 숫자와 철자를 의도적으로 섞은 이름은 표기만 보고 발음을 확정하기 어려웠습니다. 같은 숫자라도 이름마다 쓰임이 달랐습니다. 이런 항목은 공통 규칙에 넣지 않고 공개 자료를 확인하는 대상으로 남겼습니다.

| 데이터 유형 | 처리 방향 |
|---|---|
| 반복되는 클래식 표기 | 공통 구조로 발음 후보 생성 |
| 숫자·알파벳 관용 표현 | 장르·표기 조건으로 후보 분류 |
| 공식·통용 발음 확인 가능 | 근거와 함께 사전 등록 |
| 조어·고유한 아티스트명 | 공개 자료 확인과 수동 검토 |
| 출처가 충돌하는 항목 | 자동 확정하지 않고 별도 표시 |

자동화는 모든 이름을 한 규칙으로 읽는 방향이 아니라, 사람이 먼저 확인할 항목을 줄이는 데 사용했습니다. 반복 표기는 후보를 빠르게 만들고 제작 의도나 출처가 중요한 이름은 직접 확인하는 구조였습니다.

## 4. 단어가 아닌 추천 문장으로 청취

발음사전은 단어 단위로 등록하지만 사용자는 완성된 문장으로 듣습니다. 단독 발음이 자연스러워도 조사와 붙거나 긴 문장 중간에 들어가면 이름의 시작과 끝이 흐려질 수 있습니다.

```text
검수 항목: BWV 846
테스트 문장: 바흐의 BWV 846을 차분한 아침 음악으로 골랐어요.

확인
- 알파벳 약어와 작품 번호를 구분해 읽는가
- 고유명사와 조사가 자연스럽게 이어지는가
- 등록한 발음이 실제 TTS에 반영됐는가
```

등록한 항목마다 최소 한 개 이상의 테스트 문장을 만들었습니다. 주 단위 업데이트가 끝나면 같은 문장을 재생해 반영 여부를 Pass/Fail로 기록했습니다.

### 발음 오류와 끊어읽기를 따로 기록

고유명사를 잘못 읽는 문제와 문장 호흡이 어색한 문제는 수정 위치가 다릅니다.

- **발음 오류:** 특정 곡명·아티스트명·숫자를 다른 소리로 읽음
- **끊어읽기 오류:** 발음은 맞지만 작품명 중간이나 조사 앞에서 부자연스럽게 쉼

예를 들어 `베토벤의 교향곡 5번 다단조 작품 67입니다`를 `교향곡 / 5번 다단조 작품 / 67`로 나누면 각 단어가 맞아도 곡의 구조가 흐려집니다. 이 경우 발음사전 항목과 문장 호흡을 분리해 전달했습니다.

## 5. 주 단위 등록과 재검수

한 주 동안 조사한 목록은 매주 한 차례 TTS에 반영됐습니다. 기존 후보를 처리하는 동안 새로 등록된 곡명과 아티스트명도 함께 추가했습니다.

1. 주간 조사 목록과 근거 정리
2. 발음사전 등록
3. TTS 업데이트
4. 테스트 문장 재생
5. Pass/Fail 기록
6. 같은 문장으로 수정 결과 재확인

공통 규칙을 적용한 경우에는 한 항목만 듣지 않고 같은 구조를 가진 다른 곡명도 확인했습니다. 한 이름의 발음이 고쳐진 뒤 다른 이름에 새로운 오독이 생기지 않았는지 살피기 위해서였습니다.

## 6. 음성 콘텐츠 제작에 남긴 기준

일부 발음 데이터는 대화형 음악 추천 기능의 TTS와 사내 TTS에 적용됐습니다. 이 경험은 숏애니메이션에서 캐릭터 음성을 만들 때도 이어졌습니다.

- 화면에 맞는 문장이 아니라 실제로 들었을 때 이해되는 문장을 씁니다.
- 고유명사와 작품명은 전체 문장 안에서 발음과 호흡을 확인합니다.
- 모델의 내부 원인을 추측하지 않고 재현 가능한 입력과 출력 차이를 남깁니다.
- 반복 표기와 작품 고유의 예외를 구분합니다.
- 음성 수정 뒤 같은 문장으로 다시 들어 결과를 확인합니다.

AI 음성의 품질은 자연스러운 음색만으로 결정되지 않습니다. 콘텐츠 안의 인물·작품·브랜드 이름을 정확히 전달하고, 문장의 의미가 호흡 때문에 끊기지 않아야 실제 제작에 사용할 수 있습니다.
