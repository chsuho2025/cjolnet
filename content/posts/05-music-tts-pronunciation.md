## 작업 결과

2026년 3월부터 6월까지 카카오엔터테인먼트 인턴으로 음악 도메인 발음사전 제작과 TTS 품질 검수에 참여했습니다. 영어와 숫자가 포함된 곡명·아티스트명 약 3만 5천 개를 발음사전 후보로 정리하고, 초기 약 3,500건을 공개 자료로 직접 조사했습니다.

발음만 적는 데서 끝내지 않았습니다. 검색 경로, 판단 근거와 처리 시간을 함께 기록하고, 등록 뒤에는 고유명사가 들어간 추천 문장을 재생해 ==발음과 끊어읽기를 별도로 검수==했습니다. 이 데이터의 일부는 대화형 음악 추천 기능과 사내 TTS에 적용됐습니다.

## 1. 화면에 적힌 이름을 음성으로 정확하게 전달하기

음악 추천 문장에는 곡명, 아티스트명과 클래식 작품 번호가 반복해서 등장합니다. 화면 표기가 정확해도 TTS가 낯선 방식으로 읽으면 사용자는 어떤 음악을 소개하는지 바로 알아듣기 어렵습니다.

음악 고유명사는 일반적인 영문 읽기 규칙만으로 처리하기 힘든 경우가 많았습니다.

- 여러 언어권의 이름이 같은 데이터 안에 섞입니다.
- 숫자와 기호가 철자를 대신하거나 이름의 일부로 쓰입니다.
- 국내에서 널리 사용하는 이름과 원어 발음이 다를 수 있습니다.
- 클래식 곡명에는 작품명·조성·곡 번호·작품 번호·악장이 한 문장에 함께 들어갑니다.
- 정확한 발음도 조사와 붙거나 호흡 위치가 어긋나면 다른 이름처럼 들릴 수 있습니다.

발음사전은 화면의 표기를 유지하면서 TTS가 읽을 소리를 별도로 연결하는 데이터입니다. 그러나 항목을 등록했다는 사실만으로 품질이 보장되지는 않습니다. 실제 서비스 문장에 넣어 들어봐야 등록 내용이 반영됐는지, 이름의 시작과 끝이 분명한지, 앞뒤 조사와 자연스럽게 이어지는지 확인할 수 있습니다.

> **이 작업에서 분리한 두 질문**
>
> 1. 이 표기를 어떤 소리로 읽어야 하는가
> 2. 완성된 추천 문장 안에서 어디를 쉬어야 하는가

## 2. 검수 대상을 3만 5천 개로 좁힌 기준

음악 서비스에 등록된 모든 이름을 같은 우선순위로 검수할 수는 없었습니다. TTS에서 별도 읽기 기준이 필요할 가능성이 큰 항목을 먼저 찾기 위해 영어와 숫자가 포함된 곡명·아티스트명을 추출했고, 약 3만 5천 개가 후보로 모였습니다.

같은 조건으로 추출했지만 실제 오류 유형은 달랐습니다.

| 표기 유형 | 실제로 확인할 문제 |
|---|---|
| 영어 아티스트명 | 국내 통용 발음과 다른 방식으로 읽는가 |
| 숫자가 포함된 이름 | 수량·연도·철자 대체 가운데 어떤 역할인가 |
| 영문 약어 | 글자 단위와 단어 단위 읽기를 구분하는가 |
| 클래식 작품명 | 곡 번호·조성·Op.·악장을 구분하는가 |
| 외국어와 숫자의 결합 | 이름 중간에 불필요한 호흡이 생기는가 |
| 조어·활동명 | 일반 발음 규칙보다 제작자의 명명 의도가 우선하는가 |

대상 수를 정한 뒤에는 `영어니까 영문 규칙`, `숫자니까 수량 읽기`처럼 한 가지 규칙을 일괄 적용하지 않았습니다. 이름의 언어권, 장르, 활동 맥락, 국내 통용 표기와 공개된 발음 자료를 함께 확인했습니다.

## 3. 업무 범위와 기록 단위

제가 담당한 범위는 수동 조사, 조사 기록, 테스트 문장 제작과 등록 결과 확인이었습니다. 최종 규칙 정리와 적용은 담당 멘토와 협업했습니다.

| 구분 | 수행 내용 |
|---|---|
| 대상 추출 | 숫자와 영어가 포함된 곡명·아티스트명 후보 정리 |
| 수동 조사 | 검색과 공개 자료를 활용한 항목별 발음 확인 |
| 조사 기록 | 검색 경로, 확인 자료, 판단 이유와 분 단위 소요 시간 기록 |
| 문장 제작 | 등록 단어마다 최소 한 개 이상의 테스트 문장 작성 |
| 적용 확인 | 주 1회 TTS 업데이트 뒤 같은 문장으로 Pass/Fail 검수 |
| 신규 항목 | 매주 새로 등록되는 곡·아티스트 발음 추가 |
| 기록 분석 | 국적·장르·표기 구조별 반복 패턴과 예외 정리 |
| 의견 공유 | 자동 분류와 내부 읽기 기준에 활용할 규칙 후보 공유 |

발음 값만 남기면 다른 사람이 같은 항목을 다시 확인하거나, 규칙이 바뀌었을 때 판단 과정을 추적하기 어렵습니다. 그래서 한 행 안에 다음 정보를 함께 남겼습니다.

- 원본 표기와 대상 유형
- 사용한 검색어와 확인 자료
- 아티스트의 국적·활동 정보
- 국내 통용 표기와 원어 발음
- 선택한 발음 후보와 선택 이유
- 공통 규칙 적용 여부와 예외 사유
- 조사에 걸린 시간
- 등록 뒤 확인할 테스트 문장

==수동 조사 기록을 일회성 업무 결과가 아니라 다음 항목을 분류할 데이터로 남긴 것==이 이후 작업 방식 변경의 출발점이 됐습니다.

## 4. 수동 조사에서 작업 방식이 바뀐 과정

처음 약 3,500건은 곡명과 아티스트명을 하나씩 검색했습니다. 자동 분류 결과를 확인한 것이 아니라, 사람이 직접 발음 자료와 국내 통용 표기를 찾아 근거를 기록했습니다.

약 10%를 처리하자 같은 방법으로 3만 5천 개 전체를 조사하기 어렵다는 점과 동시에, 반복해서 나타나는 표기 구조가 보이기 시작했습니다. 작업 방식은 다음 네 단계로 바뀌었습니다.

1. 수동 조사로 판단 근거와 처리 시간 축적
2. 기록을 다시 읽어 언어권·장르·표기 구조별 패턴 발견
3. 반복 표기는 AI·규칙 기반 후보 분류 가능성 검토
4. 자동 확정할 항목과 사람이 확인할 예외를 분리

이 변화의 목적은 사람의 검수를 없애는 데 있지 않았습니다. 반복되는 항목은 후보를 빠르게 좁히고, 제작 의도나 출처 확인이 필요한 이름에 검수 시간을 집중하는 방향이었습니다.

## 5. 표기만 보고 읽을 수 없는 이름

숫자와 철자를 의도적으로 조합한 활동명은 일반 규칙을 적용하기 어려웠습니다.

| 표기 | 확인해야 했던 이유 |
|---|---|
| `6LACK` | 숫자 6을 수량으로 읽지 않고 `black`으로 발음 |
| `deadmau5` | 숫자 5가 철자 `s`를 대신해 `dead mouse`로 발음 |
| `3OH!3` | 숫자와 기호를 포함하지만 이름 전체의 고유한 읽기 방식이 존재 |
| `Tech N9ne` | 숫자 9가 이름의 일부인 `nine`으로 발음 |

이 사례들은 `숫자가 포함되면 숫자를 읽는다`는 규칙이 음악 고유명사에 그대로 적용되지 않는다는 점을 보여줬습니다. 같은 숫자도 이름마다 역할이 달랐고, 장르 안에서 관용적으로 사용하는 표기도 있었습니다.

국적과 장르는 우선 확인할 언어권과 자료를 찾는 단서로 사용했습니다. 다만 발음을 자동으로 확정하는 값으로 쓰지는 않았습니다. 국적이 같아도 활동명이 의도적으로 다른 방식으로 읽힐 수 있고, 장르 밖에서도 같은 표기 방식이 나타날 수 있기 때문입니다.

> **수동 조사 순서**
>
> 원본 표기 확인 → 아티스트의 활동 정보와 언어권 확인 → 공식·공개 발음 자료 검색 → 국내 통용 표기 비교 → 근거와 소요 시간 기록 → 발음 후보 작성

## 6. 반복 패턴과 사람 검토 대상을 분리

수동 기록에서 다음 구조는 반복해서 나타났습니다.

- `Op.`, 곡 번호, 조성, 작품목록 번호처럼 역할이 정해진 클래식 표기
- 같은 언어권에서 반복되는 철자와 음가
- 장르 안에서 숫자와 알파벳을 관용적으로 사용하는 이름
- 공식 자료와 국내 유통 표기에서 같은 발음을 확인할 수 있는 항목

반면 조어, 밈, 제작자의 활동명이 강하게 반영된 이름과 출처가 충돌하는 항목은 공통 규칙으로 확정하지 않았습니다.

| 데이터 유형 | 처리 방향 |
|---|---|
| 반복되는 클래식 표기 | 공통 구조로 발음 후보 생성 |
| 언어권별 반복 철자 | 우선 확인할 발음 후보 분류 |
| 숫자·알파벳 관용 표현 | 장르와 이름 구성 방식을 함께 검토 |
| 공식·통용 발음 확인 가능 | 근거와 함께 사전 등록 |
| 조어·고유 활동명 | 공개 자료 확인과 수동 검토 |
| 출처가 충돌하는 항목 | 자동 확정하지 않고 별도 표시 |

자동화의 역할은 정답을 대신 정하는 것이 아니라, 사람이 먼저 확인할 항목의 순서를 조정하는 일이었습니다. 반복 표기는 빠르게 후보를 만들고, 문화적 맥락과 명명 의도가 중요한 이름은 직접 확인하는 구조로 나눴습니다.

## 7. 등록 목표와 품질 우선순위 조정

모든 항목의 제작 의도와 원어 발음을 완전히 확인하려 하면 적용 가능한 항목 수가 지나치게 줄어듭니다. 반대로 처리량만 늘리면 잘못된 발음을 대량으로 등록할 위험이 있습니다.

수동 조사와 패턴 분석 뒤에는 다음 세 범위로 우선순위를 나눴습니다.

| 판단 범위 | 기준 | 처리 방식 |
|---|---|---|
| 정확한 발음 확인 가능 | 공식 자료와 통용 발음이 일치 | 확인한 발음 등록 |
| 명백한 오독 방지 가능 | 완전한 의도 확인 전에도 잘못된 읽기를 구분할 수 있음 | 우선 반영 뒤 추가 확인 |
| 제작 의도 확인 필요 | 조어·밈·예외 표기로 자동 판단 위험이 큼 | 수동 검토 유지 |

이 기준을 적용하면서 반복되는 표기는 내부 읽기 기준으로 묶고, 예외는 개별 항목으로 남겼습니다. 처리량과 정확도 중 하나를 포기한 것이 아니라, 제한된 기간 안에서 ==확실하게 고칠 수 있는 오류와 추가 조사가 필요한 오류를 구분==했습니다.

## 8. 단어가 아닌 추천 문장으로 청취

발음사전은 단어 단위로 등록하지만 사용자는 완성된 문장을 듣습니다. 단독 발음이 자연스러워도 조사와 붙거나 긴 문장 중간에 들어가면 이름의 시작과 끝이 흐려질 수 있습니다.

등록한 항목마다 최소 한 개 이상의 테스트 문장을 만들었습니다.

```text
검수 항목: BWV 846
테스트 문장: 바흐의 BWV 846을 차분한 아침 음악으로 골랐어요.

확인
- 알파벳 약어와 작품 번호를 구분해 읽는가
- 고유명사와 조사가 자연스럽게 이어지는가
- 등록한 발음이 실제 TTS에 반영됐는가
```

문장은 실제 추천 상황에 가깝게 만들었습니다. 고유명사를 문장 맨 앞에만 두지 않고 조사 앞, 문장 중간과 긴 작품명 뒤에도 배치해 호흡이 달라지는 조건을 확인했습니다.

### 테스트 문장을 만들 때 확인한 항목

- 앞말과 곡명 사이에서 이름의 시작이 분명한가
- 곡명 뒤의 조사와 마지막 음절이 자연스럽게 연결되는가
- 영어와 숫자 사이에 불필요한 긴 호흡이 생기지 않는가
- 작품명과 Op. 표기를 하나의 긴 문자열처럼 읽지 않는가
- 문장이 길어져도 고유명사 중간에서 끊기지 않는가

## 9. 발음 오류와 끊어읽기 오류를 따로 기록

고유명사를 잘못 읽는 문제와 문장 호흡이 어색한 문제는 수정 위치가 다릅니다.

- **발음 오류:** 특정 곡명·아티스트명·숫자를 다른 소리로 읽음
- **끊어읽기 오류:** 발음은 맞지만 작품명 중간이나 조사 앞에서 부자연스럽게 쉼

예를 들어 다음 문장은 각 단어를 맞게 읽어도 호흡 위치에 따라 의미 구조가 달라집니다.

```text
문장
다음 곡은 베토벤의 교향곡 5번 다단조 작품 67입니다.

문제 방향
다음 곡은 베토벤의 교향곡 / 5번 다단조 작품 / 67입니다.

기대 방향
다음 곡은 / 베토벤의 교향곡 5번 다단조 / 작품 67입니다.
```

문제가 들리면 해당 단어만 다시 듣지 않고 문장 전체를 확인했습니다. 앞 문장의 끝, 조사와의 연결, 전체 문장 길이에 따라 호흡이 달라질 수 있었기 때문입니다.

## 10. 클래식 곡명은 숫자의 역할부터 구분

클래식 곡명에는 작품의 종류, 조성, 곡 번호, `Op.`와 작품목록 번호가 일정한 구조로 반복됩니다.

```text
작품명 + 조성 + Op. 표기 + 곡 번호 + 악장
```

숫자가 여러 번 등장하기 때문에 각 숫자가 제목의 일부인지, 곡 번호인지, 작품 번호인지 먼저 구분해야 했습니다.

| 표기 예시 | 검수 항목 |
|---|---|
| `Nocturne in E-flat Major, Op. 9 No. 2` | Op.와 No.의 역할, 두 숫자의 관계, 조성 뒤 호흡 |
| `Symphony No. 5 in C Minor, Op. 67` | 교향곡 번호, 조성, 작품 번호의 구분 |
| `The Well-Tempered Clavier, BWV 846` | 작품목록 약어와 번호의 분리 |
| `24 Preludes, Op. 28` | 제목에 포함된 수량과 작품 번호의 구분 |

같은 구조가 여러 곡명에 반복되면 공통 기준으로 묶고, 예외가 있는 이름만 개별적으로 다뤘습니다. 한 곡의 발음만 고치는 방식보다 같은 오류가 발생하는 위치를 함께 줄일 수 있었습니다.

## 11. 주 단위 등록과 Pass/Fail 검수

한 주 동안 조사한 목록은 매주 한 차례 TTS에 반영됐습니다. 기존 후보를 처리하는 동안 음악 서비스에 새로 들어온 곡명과 아티스트명도 함께 추가했습니다.

1. 주간 조사 목록과 근거 정리
2. 발음사전 등록
3. TTS 업데이트
4. 테스트 문장 재생
5. Pass/Fail 기록
6. 같은 문장으로 수정 결과 재확인

Pass/Fail은 조사 단계에서 발음의 정답을 고르는 표시가 아니었습니다. 발음사전 업데이트 뒤 실제 문장에서 등록 내용이 적용됐는지를 판단하는 값이었습니다.

아래 표는 당시 사용한 기록 필드를 기준으로 항목명을 익명화해 재구성한 예시입니다.

| 검수 항목 | 테스트 문장 | 문제 유형 | 기대 방향 | 판정 |
|---|---|---|---|---|
| Symphony No. 5 | 다음 곡은 베토벤의 Symphony No. 5입니다. | 숫자 읽기 | 곡 번호를 작품명과 연결 | Fail |
| BWV 846 | 바흐의 BWV 846을 추천해드릴게요. | 약어 발음 | 약어와 번호를 분리 | Fail |
| 국내 통용 아티스트명 | ○○의 대표곡을 골랐어요. | 고유명사 | 국내 통용 발음 적용 | Fail |
| 한글 곡명 | 다음 곡은 ○○입니다. | 이상 없음 | 현재 발음 유지 | Pass |

Pass 항목도 기록에서 제외하지 않았습니다. 정상 출력의 기준 사례가 있어야 수정 전후를 비교하고, 공통 규칙이 다른 이름에 영향을 주지 않았는지 다시 확인할 수 있기 때문입니다.

원인을 적을 때는 모델 내부 동작을 추측하지 않았습니다. `모델이 숫자의 의미를 이해하지 못했다`고 단정하는 대신 `Op.와 곡 번호가 같은 방식으로 읽혔다`처럼 실제로 들은 출력과 기대 조건을 구분했습니다.

## 12. 같은 문장으로 재검수

발음 후보나 공통 규칙이 반영된 뒤에는 최초 Fail을 기록한 문장을 그대로 사용했습니다.

1. 기존 Fail 항목이 기대한 발음과 호흡으로 바뀌었는가
2. 같은 규칙이 적용된 다른 항목에 새로운 오독이 생기지 않았는가

개별 고유명사를 수정한 경우에는 해당 문장을 다시 확인했고, 공통 규칙을 적용한 경우에는 같은 구조의 다른 곡명도 함께 들었습니다. ==한 항목의 Pass와 규칙 전체의 안정성을 구분==하기 위한 절차였습니다.

> **재검수 기록 예시**
>
> 최초 출력: Op.와 곡 번호를 구분하지 않고 이어 읽음 — Fail
> 수정 방향: Op. 표기와 곡 번호의 읽기 단위 분리
> 재검수: 최초 문장으로 발음과 호흡 확인
> 추가 확인: 같은 표기 구조를 가진 다른 곡명에서 예외 발생 여부 확인

## 13. 음성 콘텐츠 제작에 남긴 기준

이 작업을 통해 AI 음성의 품질을 자연스러운 음색만으로 판단하지 않게 됐습니다. 콘텐츠 안의 인물·작품·브랜드 이름을 정확하게 전달하고, 문장의 의미가 호흡 때문에 끊기지 않아야 실제 제작에 사용할 수 있습니다.

- 화면에 맞는 문장보다 실제로 들었을 때 이해되는 문장을 씁니다.
- 고유명사와 작품명은 전체 문장 안에서 발음과 호흡을 확인합니다.
- 모델의 내부 원인을 추측하지 않고 재현 가능한 입력과 출력 차이를 남깁니다.
- 반복 표기와 작품 고유의 예외를 구분합니다.
- 음성 수정 뒤에는 최초 문장으로 다시 들어 결과를 확인합니다.
- 공통 규칙을 바꾸면 같은 구조의 다른 이름도 함께 검수합니다.

이 기준은 숏애니메이션의 캐릭터 음성 제작에도 이어졌습니다. 한 대사의 감정과 음색뿐 아니라 고유명사, 발화 길이, 조사 연결과 문장 사이의 정적을 별도 항목으로 나눠 확인했습니다.
